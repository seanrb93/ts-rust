# Bugs of the original game

These are bugs of the original TimeSplitters, found by reading the decompiled code and checked against the original machine code (`tools/disasm.py`): the port does what the original does, so a default build has them all.  The build with `extensions` can fix each one (`ts-game/src/manual/original-fixes.rs`, the `FIX_*` switches): a mod turns them on with a script that answers `fixes()` with the names below, and the mod Original Bug Fixes (in `example_mods/`, which is not in the repository) does it with a setting for each.  Without such a mod the game plays as the original.

| name | where | what goes wrong | the fix |
|---|---|---|---|
| `sleeping_enemies` | `aiTickBefore` | Every fourth frame the game tests one sleeping enemy (state 0x2000) for seeing the player, from the place `checksleepplayer`. It moves that place on only past enemies that are awake, so it stays on the first sleeper for ever, and the sleepers after it wake only when they come on screen. | The place moves on after each test. |
| `custom_map_stats` | `gameStatusUpdated` | Outside the story a match adds 1 to its level's record of the statistics (30 records of 36 bytes from +320). A map of the map maker is level 100, so the word written is 3952 bytes in, past the 2804 bytes of the statistics: in the next sign-on's profile, one of its best times (and any time counts as done for the unlocks). The story's branch has the test of the level. | The record is written only for the levels 0 to 29. |
| `seen_by` | `playerAutoAimTick` | When a player sees another character, the character's +2776 (who saw it last, which a bot uses to turn on an attacker) is written unless `currentplayer` is dead: the player last drawn, not the player of the pair. | The player of the pair is asked. |
| `kill_stat` | `propDamage` | The statistic 68 of a kill goes to the slot `prop + 4` of the killer, which is the kind of its prop (the number of its model): `StatsAdd` drops it from 14 up, or counts it for the wrong player. The medal that needs it (47) is never earned. | The killer's own slot. |
| `pickup_gun` | `pickupPropTick` | A character of role 1 may take a weapon by flag 2 of a gun's record, but the record read is the one with the number of the weapon's combination, not the combination's gun (combination 1 is gun 0, 3 is gun 1, ...; 30 to 32 are past the 30 guns). | The combination's own gun. |
| `medal_mean` | `medals` | The mean of statistic 46 starts from its average and then adds every slot's value, so it is the average and the total over the slots: too high, and medals 22 and 42 are harder to get. | The sum starts from 0. |
| `spawn_lists` | `enemyAddToBagList`, `enemyAddToPropList` | An entry is written before the count is tested, so the 7th bag pad is written over the list of characters (`chr`) and the 11th base over `aiexplosiondata`. Only a level with that many has it. | A full list takes no more. |
| `double_end` | `gameLevelCompleted` | When the time runs out the level is completed and the mode's tick still runs in the same frame; if the mode ends the level too (a score limit), `gameStatusUpdated` runs twice and the match is counted twice. | A completed level is not completed again. |
| `defend_pad` | `enemyDefend` | An enemy defending with no pad (-1) chooses one, and then every way writes the old pad (-1) back, so it walks to the pad -1 (the 28 bytes before the pads). | The pad chosen is kept. |
| `route_reset` | the pad attack of `enemyAttack` | The route is to be planned again when the target's pad is not the one the enemy went to, but the test reads the pad after writing the new one into it, so it is never true and the enemy walks its old route out first. | The pad from before is compared. |
| `rejected_pickup` | `enemyCheckHealth` | The best health or armour pickup is made the enemy's target while it looks, and stays so when it then decides against it; with no enemy to go after, `selectTarget` keeps the pickup. | The target from before is put back. |
| `camera_room` | `camTick` | The following camera tests for walls on the line from the eye to the camera, from the room of the camera's end: when that is another room (or none) walls between are missed and the camera looks through them (camera modes 1 and 2). | The room of the eye (`player + 796`), as the other line tests from the eye. |
| `limb_normal` | `hittestLineCylinder` | The point of a limb's axis nearest the hit is taken as the bottom minus the axis part, where it is plus, so the direction of the hit (for sparks and blood) leans along the limb. | Plus. |
| `map_cursor` | `mmfileTick` | After a map is saved the list remembers the map's number less the parent row ("New map"), so it comes back one row above the map saved. | The map's own number. |
| `arcade_map_cursor` | the map page of the arcade (`0x3aff80`) | The page reads the map it should come back on, but nothing ever sets it (only -1), so it always comes back on the first map. | The map loaded is kept. |
| `name_length` | the sign-on name page | The names are 30 bytes apart and the editor takes 30 letters with the end after them, so a name of 30 letters blanks the next player's first letter. | 29 letters. |
| `paste` | `mmDoPaste` | A paste that cannot place one of the objects frees that one and the held group, and those placed before it stay; with no objects left the rest are dropped and the paste counts as done. | The map goes back to the copy made at the start of the paste. |
| `camping` | `playerCampingDetection` | Bots pass over a player who has camped (stayed near one place) more than 4 seconds, but the time (+880) is cleared every frame and nothing adds to it. | It grows by the seconds while the player stays within 6 units of the place, and starts again when the player leaves. |
| `pushed` | the push of `playerTick` (mode 1) | The push left is taken off along x three times and never along y and z, so a push with a y or z part never ends. Nothing in the game's levels uses the mode. | Each axis takes off its own part. |
| `story_link` | `lvInitStoryState` | The case of level 5 has no end, so it goes on into the line of level 9, which turns off the link from pad 1067 to 1070. Level 5 has no such link, and `padGetLinkNum` gives 0 when it finds none, so link 0 of level 5 (pads 1002 to 1005, a real way) is turned off on every difficulty and routes cannot use it. | Level 5 stops after its own links. |
| `mirror_glass` | `particleGlassTick` | The fade of the shards of a mirror (flag 256) is 0.7 − 4·(age − 1) where 1 − 4·(age − 0.7) is meant: the shards are 1 until 0.7 s, then jump to 1.9 (nearly twice the full colour) and are gone at 1.175 s. | 1 − 4·(age − 0.7). |
| `option_arrows` | `draw_menuitem` | The loop that finds the widest text of a choice measures the current choice every time, so the left arrow is placed by the current text and moves when the choice changes. | Each choice of the list is measured. |
| `stats_percent` | `statistics_pageDrawInfo` | A rate under 1% is printed with "%.2f%" from the fraction, not the percentage, so a half percent shows as 0.01%. (`drawStats` does it right.) | The percentage. |
| `team_rankings` | `drawRankingsTable` | The row of a team is held by the first character of the team found; the player's row is found and marked by comparing characters, so only that one player of the team sees it marked. | The team of the row is compared. |
| `spawn_glow` | `specialfxCreate` kind 9 | Colour 3 of the glow of a pickup coming back falls into colour 0's orange; the other effects (kind 1) have green for colour 3, so the glow is orange half the time and never green. It may be meant. | Green. |
| `idle_animation` | `enemySetIdleAnimation` | Outside the story the test of animation 3 having finished is made only while 450 or 451 plays, where it is never true; while 3 plays the function picks again every frame, so 3 is restarted or replaced at once and the enemy fidgets with 450 and 451 all the time. | Animation 3 plays to its end first. |
| `wall_slant` | `hittestMoveCircleToLine` | The gap to the line is measured along its normal and then taken as a distance along the move, which is too short by the cosine of the angle, so a character that comes at a wall at a slant stops short of it. (The end of the wall it is tested against is also chosen from where the move starts; that is not changed.) | The gap is turned into the distance along the move. |
| `defocus` | `ipDefocus` | The third pass of the screen is drawn one to the right again, the same as the first, so the blur is twice as much sideways as down. | One down and one to the right. |
| `blend_length` | `calMatrices` | When the animation blending in does not loop and runs past its end, its time is set to the length of the other animation. | Its own length. |
| `loop_root` | `calMatrices` | When the animation blending in loops and wraps, its root movement is to lose the movement of a whole loop (the last frame less the first), as the other slot does, but it adds the first frame and takes it away again, so the character jerks back for a frame. | The last frame is taken away. |
| `pad_floor` | `padSetRoomNums` | The height of a pad is set from `lastfloorheight` whether a room was found or not; `moveFindRoom` sets it only when it finds one, so a pad with no floor under it gets the floor of the pad before. | The pad keeps its own height. |
| `preload_order` | `preloadAddFile` | The preload list is sorted by the sector of the file on the disc (+8), which the other adds set and this one never does, so a plain file goes where an old entry's sector puts it. Only the order of loading changes. | The sector of the file is set. |
| `texture_slots` | `emGetNextPos` | A texture of more than one block (up to 16) is put in a free slot and the slots after it, which are not tested, so with the texture memory nearly full it can take slots in use or go past the table. | All its slots must be free and in the table. |
| `decal_room0` | `decalRemoveFromDrawList` | A decal that is alone on its list clears the head of the list only for a room above 0, so room 0's head stays on the decal after it is used again elsewhere and the lists get joined. | Room 0 too. |
| `electricity` | `electricityPropTick` | The lines of the electricity are the chunks 1 to 12, but chunk 0 reads the word before `electricityOn` (the last of another table) and, when that is set, writes a texture offset over the timer of line 11. | Chunks that are not lines are left alone. No level of the game has electricity, so this does nothing in play. |
| `sound_lock` | `soundTick` | The lock of the sound transfers set in state 2 is let go only in state 5; a sound of no size goes from state 4 to 0 and keeps it on, so the on-demand sounds (the announcer) wait until the sound restarts. | The lock is let go. |
| `multitap_slot` | `controllerTick` | The number of slots of a port is a count, but the test is `slot <= count`, so the slot after the last is asked too. No effect in the program's controllers. | `slot < count`. |
| `pad_no_motors` | `step_pad_state` | A pad with no motors is set to state 99 (working), then the motors are set anyway, and when that succeeds the state goes on to 100, which nothing reads. The program's controllers all have motors. | It stays at 99. |
| `aim_pitch` | `rotateChr` | The up and down aim at a target is worked out from a direction on the stack that only targets of the kinds 1, 8, 64 and 256 write; for the others the words nothing wrote are read. | Towards the target's place. |
| `chase_route` | `followTarget`, `trackTarget` | A chaser plans its route again when its target's pad (+684) changes, but only on its own turn (`updatedistindex`, one character a frame), and the new pad is stored on every frame. A change seen off the turn is lost, so the chaser walks its old route to where the target was, and with many characters that is the usual case. | The old pad is kept until the turn comes. |
| `kill_spree` | `StatsKillMade` | The killing spree (+1360 of the match statistics, statistic 7, "Longest killing spree") goes up by 1 at a kill within 2 seconds of the last, but nothing starts it again at a slower kill, only a death. It counts every quick kill of a life, not the longest run of them, and the Longest Spree medal is easier to get. | A slower kill starts it again at 1. |
| `on_pad` | `enemyOnPad` | A defending bot is not to choose a pad another character is heading for. The bots are numbered after the players, but the test looks at the first `numactivechars` records, players among them, and misses the last bots; and it answers with the number found, so character 0 counts as nobody. | The bots are tested, and a found one is never 0. |
| `zombie_turn` | `setZombieAnimation` | A zombie's turn animation (520 and 522 to the left, 521 and 523 to the right, without and with a weapon) is started again unless both of a side play, which never happens, so it is started again every frame while the zombie turns past 45 degrees and stays at its start. The TimeSplitter's turn asks for either. | Either one playing keeps it. |
| `room_light` | `roomlightTick` | A flickering room light (kind 3) on a frame with no update (a paused frame, or most frames at a high frame rate) skips its roll but still blends its colours, with the strength the room before it left, or for the first room a register never set. | The light keeps its colour on such a frame. |
| `pickup_sound` | `pickupPropTick` | The sound of picking up a gun is chosen by the gun in hand, which is the gun picked up only when the game switches to it; holding grenades or mines, every gun picked up sounds like ammunition. | The sound of the gun picked up. |
| `pad_zero` | `enemyCheckValidPad` | A character whose nearest pad is not its own is put on that pad only if its number is above 0; `closestpad` gives -1 for none, so pad 0 is left out and a character near it keeps a wrong pad and routes from it. | Pad 0 counts. |
| `highlight_depth` | `findHighlightPad` | The map maker's cursor picks between two pads close on screen by their depth, but the depth is cut to a whole number (0 on screen) before it is compared, so the one earlier in the list always wins, even behind the other. | The depth keeps its fraction. |
| `bag_message` | `propDropBagOnDrop` | When a bag is dropped on a team's drop by someone of another team, the first character of that team gets the message with no test that it is a player; a bot has no HUD, and past the fourth character the text is written after the HUD records. The other branch tests it. | Only a player gets the message. |
| `escort_list` | `enemyAddToEscortList` | The escort is written before the count is tested, so a sixth escort and every later one goes into the word after the list of five. No level of the game is known to have six. | Nothing is written past the list. |

Also seen, not fixed:

* `enemyExplosionNearby` never does anything: the count of `aiexplosiondata` is only set to 0, and the function writes its own place over the records it reads; even working, it only calls `checkInFront` and drops the answer.
* `particleNewGlass` writes zeros over the machine code of `soundStartRange`; in the port the code is not in that memory, so nothing happens.
* `gunShouldSwitchTo` tests the addresses of two fields (always true) where it meant their values; what it meant is not clear (a gun number of 0 is the pistol), so it is left as it is.
* `weatherTick` pushes the z part of the wind out by the sign of x (offset 48 where 56 is meant), but nothing reads the wind it stores: banners and streamers work theirs out from the time.  `gunGetGunAmmo` tests the addresses of fields (always true) where it meant their values.  `gunFire` falls from the bullet kind 10 into 11, which writes over its sizes, and nothing reads them.  `rotateChr` reads the word before `dropspawn` as a drop when a bot of state 4 has no drop of its team.  `lvGetPseudoRandomPadExtref` rejects every pad unless the flag of the greatest distance is given, and every caller gives it.
* `bgFloorBBIntersection` compares the top of the floor box with the top of the box where the others compare it with the bottom; nothing calls it.  `memReset` clears the level memory and then writes "mem_mark" over all of it.  The memory card's sequencer asks the free entries of the root folder and never reads them.  A remote prop's state 4 writes the weapon it has just found equal.  `setTimeSplitterAnimation` writes 0 to the style it then tests, so the other idle styles never play.  These do nothing in play.
* The pad attack of a bot waits (skill + 0.5) + 3 seconds in one place and (skill + 0.5) × 3 in another; the door walls of kind 4 write only the first box's bones; the camera of modes 4, 5 and 9 turns its angles into 360 to 720 (only sines and cosines read them). These may be meant, or do nothing.

Four bugs of the port itself (the original is right) were found in the same searches and are fixed in every build: `enemyChooseDefendPad` lost the store of the height of the direction it tests, `gunReload` read the room of the first shotgun shell from the wrong address, `lvInitStoryState` turned off a link on level 27 that the original does not (the link from pad 1067 to 1070, which is not there, so link 0), and `soundCalcVol` started its nearest distance from a word of text (0x3afd00) where the original has the greatest float (0x3ae300).
